# 关于站点

本网站用于沉淀机械专业学习、设计思考与工程实践中的笔记、规范与案例，也作为公开输出的长期源站。
目标可以概括为一句话：搭建沟通之桥，研习行业标准，分享学习见解。

!!! abstract "站点定位"
    这不是一个追求复杂功能的商业官网，而是一个更重视内容积累、结构清晰与长期维护的专业文档站点。
    若站内内容对您有所帮助，欢迎继续关注；若您愿意分享经验、勘误、建议或补充，也欢迎与我联系。


!!! warning "外部链接提示"
    本站所有外部链接，页面内容、可访问性与链接时效可能变化；访问前请自行判断网络环境、设备安全与链接可信度，并保持审慎态度。

!!! note "发布说明"
    站内涉及点名提及的人物，已尽量逐一沟通并获得发布授权；未获授权或不宜公开的内容，则不予写入，或已做必要处理。


## 站点概览

本站更关注长期可维护的专业内容，而不是短期的页面热闹。它既是我个人持续整理机械相关知识的工作台，也是一个愿意逐步开放协作、持续修订的公开文档站点。

目前本站内容主要围绕以下几个方向展开：

- 机械设计中的基础原则、思路与案例
- 建模、出图、命名和版本管理等可执行规范

- 学习路径、工作流与可复用的方法

## 关于备案 { #filing }

本站目前采用的是静态文档站的部署方式，基本链路可概括为：

`本地写作 Markdown -> Git/GitHub 版本管理 -> GitHub Actions 自动构建 -> Vercel 托管 -> Cloudflare DNS -> 自定义域名访问`

其中，服务器可以理解为实际对外提供网站内容的“源站”，也就是网站文件最终被托管和访问的位置；CDN 则更像分发与加速层，负责把用户请求导向合适的节点，减少访问延迟，并提升访问稳定性。换句话说，DNS 解决“域名指向哪里”，CDN 解决“内容如何更高效分发”，而源站决定网站内容真正托管在哪里。

按照当前架构，本站的内容版本管理在 GitHub，静态站点托管在 Vercel，并通过 Cloudflare 管理 DNS 与访问链路。这意味着本站实际使用的源站服务器并不在中国大陆境内，因此无法按国内服务器网站的路径进行 ICP 备案。若要完成备案，通常需要将网站源站迁移到中国大陆境内的云服务器，例如阿里云、腾讯云等，并按服务商流程提交备案材料。

也正因为网站没有 ICP 备案，在微信内打开 `https://www.bridgezhang.com/` 时，曾出现过外部链接访问警告。该提示并不代表网站内容本身存在违规问题，但会影响读者从微信环境直接访问本站。

后续我向腾讯公司微信团队提交了申诉。经审核，微信团队确认链接 `http://bridgezhang.com` 不含违规内容，外部链接在微信内的直接访问已恢复。

## 开源协作

本站希望以开放、克制而持续的方式整理内容。若您对机械设计、加工、测量、检验或相关工作流有自己的见解，欢迎参与协作。

您可以选择：

- 在 GitHub 提交 `Issue` 或 `Pull Request`
- 通过邮件发送建议、勘误或补充材料
- 先阅读 [协作说明](collaboration.md)，再按更完整的流程参与

如果您并不熟悉 GitHub，也没有关系。直接通过邮件联系，同样很欢迎。
